# Baking on the way: a morning run planner for a one-van bakery

ITOM4336 final project, Faith Doyle and Sana Shahid.

A fictional Dallas bakery bakes kolaches **in a rented oven inside its van while it drives**, so cafés
get them warm. Every night, customers' orders arrive by 9 PM. This system turns the order sheet into
Rosa's run sheet: **which oven to rent, when to leave, which orders to say no to, the stop order, and
the minute to load each tray** so it comes out just before its stop. It plans for **profit**, not
miles: a late or stale tray is discounted or refused under the freshness contract. After each morning
it reads the van's delivery log and learns real Dallas drive times.

**Dashboard:** `docs/index.html` (GitHub Pages: _add URL once published_). Phone first.

> All business data is generated by a seeded script; the patterns are ones we built in.
> Road times are real (OpenStreetMap) and ingredient prices are real (BLS). See `source-index.md`.

## How to run

Works on Windows, macOS and Linux with Python 3.11+. No secrets are needed: without a database
URL everything is stored in a local SQLite file.

**1. Set up (once)**
```bash
python -m venv .venv
# Windows:            .venv\Scripts\activate
# macOS / Linux:      source .venv/bin/activate
pip install -r requirements.txt
python -m bakery setup            # loads customers + BLS prices into the database
```
Raw data is already in `data/raw/`. To rebuild it yourself: `python -m bakery generate`
(seed 4336), `python -m bakery prices` (BLS API, no key), `python -m bakery roads`
(OpenStreetMap; needs `pip install osmnx scikit-learn`, about 2 minutes; falls back to straight-line × 1.3).

**2. Build the history (once, about 30 s):** plans, simulates and learns from 55 mornings.
```bash
python -m bakery backfill --until 2026-11-06
```

**3. The nightly workflow.** In Claude Code, run:
```
/plan-run data/raw/orders/orders_2026-11-09.csv data/raw/logs/log_2026-11-06.csv
```
It cleans and checks the orders, plans (optimizer loop), has the `plan-reviewer` subagent check
the plan independently, exports the dashboard data, **asks you (Rosa) to approve**, then commits and
pushes. Without Claude Code, the same steps by hand:
```bash
python -m bakery ingest-log data/raw/logs/log_2026-11-06.csv
python -m bakery clean data/raw/orders/orders_2026-11-09.csv
python -m bakery plan 2026-11-09
python checks/verify_plan.py 2026-11-09
python -m bakery export && python checks/validate_site.py
python -m bakery approve 2026-11-09 && python -m bakery export
```
**4. Let the morning happen** (stand-in for the real van): `python -m bakery drive 2026-11-09`
writes `data/raw/logs/log_2026-11-09.csv`, which you pass to the next night's `/plan-run`.

**5. Look at the dashboard:** `python -m http.server -d docs 8000` and open http://localhost:8000.

**Checks:** `python -m pytest -q tests` · `python checks/measures.py` (the three goals) ·
`python checks/evaluate.py` (small evaluation, 6 cases).

### Optional: cloud MySQL (instructor feedback)
Create a free MySQL service on Aiven, then put this in a file named `.env` (git-ignored):
```
DATABASE_URL=mysql://avnadmin:PASSWORD@HOST:PORT/defaultdb?ssl-mode=REQUIRED
DB_SSL_CA=C:/path/to/ca.pem     # optional, Aiven's CA certificate
```
Every command then reads and writes the cloud database instead (run `setup` and `backfill` once).

## Results so far (55 simulated mornings, `python checks/measures.py`)
| Goal | Target | Result |
|---|---|---|
| Profit per morning vs Rosa's rule of thumb | +15% | **+$231/morning** ($258 vs $28), better on 55/55 mornings |
| Kolaches delivered < 15 min from the oven | ≥ 85% | **94%** (old way 33%) |
| Worst-stop arrival error after learning | ≤ 5 min | **1.5 min** (2.0 in the first 10 mornings); the plan's profit over-promise fell from $52 to $11/morning |
